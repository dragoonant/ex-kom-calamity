# 10 - Battle rules spec (the battle slice: M1 rules, M2 playable, M3 AI)

From 3d-game-generation `templates/spec-10-rules.md`. **The spec is the product** (KB rule 2): the engine in `src/engine/` implements exactly this, tests under `tests/` are named by these ids, and every ambiguity met while building is logged in section 17 as `RULING: <id> | <what we did> | <why>` with a status word instead of blocking. Where this spec and `docs/GAME-DESIGN.md` disagree, this spec wins. Every number written as `section.key = N` is a key in `src/data/tuning.json` (default shown; `npm run validate:data` checks that the two agree); unit and weapon numbers live in `src/data/units.json` and `src/data/weapons.json`. The engine reads numbers only from data. Every number is a first guess *(tune)* until a `sim` result says otherwise (KB rule 30).

**Scope (KB rule 6):** one raid on one building in its street (`PLAN.md` D20, MAP-10; the M2 city block of MAP-7 stays in the data but is no longer played), real time with pause, hidden hosts among citizens, destructible walls and floors. Nothing from the city layer (M5 on). The client rules (TIME-6, SAV-3..6), the city block (MAP-7, MAP-8), structure (section 19) and charges (section 20) arrived with M2; taking (section 21), the AI (section 22) and the bench (section 23) with M3; everything else is M1. Every proper name is a placeholder (`PLAN.md` D10); none is taken from the inspiration (`docs/GAME-DESIGN.md` section 5).

Source documents: `docs/GAME-DESIGN.md` sections 2 and 3, `PLAN.md` D3, D4, D6, D7, D16, Q3, Q5; KB `recipe.md` sections 2, 3, 5 and 11.

## 0. Engine contract (ARCH)
- **ARCH-1** `createGame(setup) -> State`. `setup = { battleId: string, seed: number, tuning?: Partial<Tuning>, roster?: Roster }` (ARCH-11). The battle file (`src/data/battles/<battleId>.json`) names the map, the squad and every spawn; `tuning` overrides are merged key by key per section and stored in `state.tuning`, so a replay carries its own numbers.
- **ARCH-2** `step(state, action) -> { ok: true, state, events } | { ok: false, state, reason }`. Pure: never mutates its input, never throws on a bad action (a rejection returns the same state object and a readable reason). Only programmer errors throw.
- **ARCH-3** `legalActions(state, side) -> Action[]` is **never empty**: `tick` is always in it, for every side, before and after the battle ends (TIME-5).
- **ARCH-4** `query.*` computes every number a client could show (section 14). The client never does rules maths.
- **ARCH-5** `view(state, side) -> State` hides what that side cannot know (section 13). An AI reads only its own view.
- **ARCH-6** State is **plain JSON**: no classes, Maps, Sets, functions, `undefined`, `NaN` or `Infinity`. `JSON.parse(JSON.stringify(s))` deep-equals `s`.
- **ARCH-7** Randomness comes only from an sfc32 RNG whose four 32-bit words live in `state.rng`. Same seed plus the same action list gives the same state, byte for byte.
- **ARCH-8** Every resolved roll emits an event with its full breakdown (FIRE-9, DMG-4); every other change that a client would draw emits an event (moves, doors, reveals, downs, the end).
- **ARCH-9** `state.log` keeps the accepted actions in order; consecutive `tick` actions are stored as one entry `{ type: "tick", count }`. `replay(setup, log)` rebuilds the state and `hashState(state)` is a 32-bit FNV-1a of its JSON text.
- **ARCH-10** No DOM, three.js or React import anywhere under `src/engine/`; the engine depends only on `src/data/`.
- **ARCH-11** (M7, the join) An optional **roster** fills the battle file's spawn points from the city: `squad` (`{ name, template?, weapon? }[]`) takes the squad spawn points in order, at most as many as the file has, each keeping the file's template or weapon when it names none; spare squad points stay empty. `hostiles` (`{ host, taker, fighter }`) fills the file's hostile spawn points in file order, fighters first, then takers, then hosts; spare hostile points hold citizens, and when there are more hostiles than hostile points the overflow stands on the citizen points as hosts. Without a roster the file is used as written, so every replay, golden and bench is unchanged. An unknown template, a non-agent squad template or an unknown weapon is a programmer error (throws).

## 1. Time (TIME)
- **TIME-1** Time is counted in ticks; `time.ticksPerSecond = 10`. `state.tick` starts at 0.
- **TIME-2** Time advances **only** through the `tick` action. Pause is the absence of ticks: orders (section 4) are accepted whether or not ticks are flowing, so the player gives orders paused or live.
- **TIME-3** One `tick` resolves in this order: (a) every living unit in id order acts: with a pending charge it arms it (BLAST-2); otherwise it picks its current target (FIRE-2) and either aims or fires at it, or, with no current target, advances its move order (section 5); (b) proximity reveals (HIDE-3); (c) `tick` increases by 1; (d) the end check (section 12).
- **TIME-4** `advance(state, seconds) -> { state, events }` applies `round(seconds * time.ticksPerSecond)` tick actions and concatenates their events. It is the deterministic hook a client's fixed-step loop and the tests drive (KB `recipe.md` section 11); nothing in the engine reads a clock.
- **TIME-5** After the battle is over (END-5), `tick` is still legal and accepted; it returns the same state (no log entry, no event).
- **TIME-6** The client's loop (M2) owns no clock of its own: each frame it feeds wall time, clamped to 0.25 s and multiplied by the speed setting (1, 2 or 4), into an accumulator and issues `floor(accumulated * time.ticksPerSecond)` ticks through `advance` (TIME-4), keeping the remainder. A paused frame feeds nothing. The same `advance(seconds)` is exposed on the page as `window.__ekc.advance(seconds)` so tests drive time without a frame clock.

## 2. Map (MAP)
- **MAP-1** The battle takes place on one map of `width` x `depth` tiles on `levels` levels. A tile is `{ x, y, level, kind, open, material, hp }`, `x` east, `y` south, level 0 the ground. **Every tile carries a level, a material and health** (`PLAN.md` D16; STR-1).
- **MAP-2** Tile kinds and their map legend: `ground` (`,`, outdoors, passable), `floor` (`.`, indoors, passable), `wall` (`#`, impassable, blocks sight), `door` (`+`, passable; blocks sight while closed), `stair` (`>`, passable, connects levels, MAP-4), `window` (`=`, impassable, does not block sight), `rubble` (`%`, passable, does not block sight: what a destroyed wall, door, window or ground floor leaves, STR-4), `void` (space, impassable, does not block sight: open air beside an upper floor, or a collapsed floor).
- **MAP-3** `open` is `false` on every tile except a door that has been used: it becomes `true` forever when a unit steps onto a `door` tile (MOVE-7).
- **MAP-4** A `stair` tile at `(x, y, L)` connects to the tile at `(x, y, L+1)` and to `(x, y, L-1)` when that tile is also a `stair`. There is no other way between levels.
- **MAP-5** Distance between two tiles on the same level is Euclidean between tile centres: `sqrt(dx^2 + dy^2)`. Adjacency for melee is Chebyshev distance 1 (the eight neighbours). Tiles on different levels have no distance.
- **MAP-6** The first map is `civic-savings-branch`: a two-floor bank branch with a roof (levels 0, 1, 2), 16 x 12 tiles, the street around it on level 0. The building belongs to a placeholder organisation, "Civic Savings"; the name appears only in data and may change. Since M2 it is the test and sim map (battle `first-raid`); the playable ships the block of MAP-7.
- **MAP-7** A battle map may be a **city block** (`PLAN.md` D16): several buildings around streets and a courtyard, each with its own floors, **up to six floors plus a roof**, so a map has up to 7 levels. A battle may start in the street and move indoors. The block is `halcyon-block`: 60 x 60 tiles on 7 levels with five buildings of 1, 2, 3, 4 and 6 floors; the battle `block-raid` starts the squad in the street. Since D20 the block is kept as data and tests and is not offered by the client. Every name is a placeholder.
- **MAP-8** A map file carries, besides `width`, `depth` and `levels[].rows` (MAP-2): an optional `levels[].materials` grid and a `materialKey` (STR-1), and a `buildings` list of `{ id, name, x, y, w, d, floors }` (footprint and floor count; the roof is the level `floors`). The rules read only tiles; `buildings` is for the client's labels and the city layer (M7). A block map is written by `npm run map:make` (`tools/make-block.ts`) from a building list, and the JSON it writes is the data.
- **MAP-9** (M4) A map file may also carry **set dressing**: each building an optional `style` (`residential`, `office`, `bank`, `depot` or `automat`) and the map an optional `props` list of `{ kind, x, y, level, yaw? }`, one prop per tile, each standing on a `floor` or `ground` tile, `yaw` in quarter turns (0 faces south). The kinds are listed in `src/data/index.ts` (`PROP_KINDS`) and drawn as `docs/art/tile-set.md` says. **The rules never read a style or a prop**: `parseMap` ignores them, they block nothing, hide nothing and take no damage of their own; the client draws a prop by the health of the tile under it (intact, damaged, gone). `validate:data` checks the kinds, the tiles and that no prop stands on a spawn.
- **MAP-10** (`PLAN.md` D20) A **raid site** is a map of **one building** of 1 to 3 floors plus a roof, standing in a ring of street 4 tiles wide, the squad on the west street and every hostile inside the building. The playable raids are `automat-raid` (`sunbeam-automat-site`, 1 floor), `depot-raid` (`depot-7-site`, 2 floors) and `savings-raid` (`civic-savings-site`, 3 floors), listed in `src/data/index.ts` as `RAID_SITES`; each building is the block's plan of the same name moved to its own map, written by `npm run map:make`. The city layer (M7) will pick the site from the alerted building; until then the title offers all three.

## 3. Units (UNIT)
- **UNIT-1** Sides: `agency` (the player), `hostile` (hosts and takers), `civilian` (citizens; engine-driven, never gives orders).
- **UNIT-2** A unit is created from a template in `units.json` with `hp`, `armour`, `aim`, `moveTicks` (ticks per orthogonal step), `sight` (tiles), `weapon` (a `weapons.json` id or none), `disguised` (HIDE-1) and `defaultStance` (STANCE-2). Agents may override the weapon per battle file.
- **UNIT-3** Unit ids: agents `a1..aN` in squad order; every other unit `u1..uM` in order of `(level, y, x)` of its spawn tile, so an id says nothing about what a unit is.
- **UNIT-4** A unit with `hp = 0` is **down**: it acts no more, takes no more orders, stops blocking movement (MOVE-5) and is never a legal target. Its body stays on its tile in the state.
- **UNIT-5** Templates: `agent-t1` (plain security gear, `PLAN.md` D7 tier 1), `agent-t2` (the moulded shell-plate suit, D7 tier 2: more health and armour; fielded only through a roster, ARCH-11), `host` (a taken-over citizen, disguised, pocket pistol), `taker` (the organism, fast, melee, never disguised; its bite takes citizens, TAKE-1), `fighter` (M3: the purpose-grown fighter of `PLAN.md` D14, a headless column on three stilt legs; armoured, lash whip at range 5, one breaching charge), `citizen` (unarmed). Numbers are in `units.json`; the JSON wins.

## 4. Orders (ORD)
- **ORD-1** Actions: `{ type: "tick" }`; `{ type: "move", side, unit, to: { x, y, level }, run? }` (POSE-3); `{ type: "fire", side, unit, target }`; `{ type: "stance", side, unit, stance }`; `{ type: "posture", side, unit, posture }` (POSE-2); `{ type: "halt", side, unit }`; `{ type: "blast", side, unit, at: { x, y, level } }`; `{ type: "withdraw", side: "agency" }`.
- **ORD-2** An order is rejected (`ok: false`) when the battle is over, the unit does not exist, is down or does not belong to `side`, or the side is `civilian`.
- **ORD-3** `move` is legal when `to` is a passable tile other than the unit's own, not held by a living unit, and a path exists (MOVE-2). It replaces any earlier move order and keeps the fire target.
- **ORD-4** `fire` is legal when the target is a living unit of another side that `side` can currently see (SEE-5), at any range. It sets the unit's **explicit target** (a new target resets `aimProgress`; the same target again changes nothing); the unit fires when it can (FIRE-1) and otherwise keeps moving. A `fire` on a unit that appears to be a citizen is legal: the player may shoot a suspect, and pays for it in the counters (CIV-3).
- **ORD-5** `stance` is legal for any stance other than the unit's current one (STANCE-1).
- **ORD-6** `halt` is always legal for a living own unit: it clears the move order, the explicit target, any aim in progress and a pending charge (BLAST-1).
- **ORD-7** `withdraw` is legal for `agency` while the battle is not over; it ends the battle at once (END-4).
- **ORD-8** `legalActions(state, side)` lists, in this order: `tick`; for each living unit of the side in id order, `halt`, each other `stance`, each other `posture` (POSE-2), `move` to every reachable tile (QRY-3, walking; RULING POSE-3), `fire` at every legal target, `blast` at every legal tile in tile-index order (ORD-9); then `withdraw` for the agency. For `civilian` and for a finished battle the list is `tick` alone.

- **ORD-9** `blast` is legal when the unit has `charges > 0` and `at` is a tile on the unit's level, other than its own, within `blast.throwRange = 6` tiles (MAP-5) that the unit itself sees (SEE-2). It sets the unit's pending charge (BLAST-1), replacing an earlier one; move and fire orders are kept and resume after the detonation.

## 5. Movement (MOVE)
- **MOVE-1** Movement is 8-directional on a level. A diagonal step is allowed only when both orthogonal tiles it passes are passable (no corner cutting). A level step is a move between a `stair` tile and the tile above or below it (MAP-4).
- **MOVE-2** Step cost in ticks: orthogonal `unit.moveTicks`; diagonal `round(moveTicks * move.diagonalCostPercent / 100)`, `move.diagonalCostPercent = 141`; level step `round(moveTicks * move.stairCostPercent / 100)`, `move.stairCostPercent = 150`. A step onto a `rubble` tile costs `round(cost * move.rubbleCostPercent / 100)` of what it would otherwise cost, `move.rubbleCostPercent = 200`. Running and crouching then scale the cost (POSE-3); no step costs less than 1 tick. Paths are cheapest-first (Dijkstra) over passable tiles, ignoring units; ties break by the neighbour order east, south, west, north, then the four diagonals clockwise from north-east, then up, then down.
- **MOVE-3** A move order holds the remaining path and a `progress` counter. Each tick in which the unit has no current target (FIRE-2), `progress` rises by 1; when it reaches the cost of the next step the unit moves onto that tile, `progress` returns to 0 and a `moved` event is emitted. On the last step an `arrived` event follows and the order clears.
- **MOVE-4** A unit with a current target does not advance its move order (it stands and fights); the order survives and resumes when the target is gone.
- **MOVE-5** A tile holds at most one living unit. Down units do not block. When the next tile is held, the unit waits (`progress` stays at the step cost) and counts `blockedTicks`; at `move.blockedWaitTicks = 5` it replans around every held tile; if no path remains the order clears with a `moveBlocked` event. When the next step is no longer a legal step at all (its tile was destroyed or collapsed, STR-4), the unit replans at once around nothing but the map, and the order clears with `moveBlocked` when no path is left.
- **MOVE-6** Reaching a tile is instantaneous for rules purposes: the unit is on exactly one tile at every tick, the one in `unit.x, unit.y, unit.level`.
- **MOVE-7** Stepping onto a closed `door` opens it (`doorOpened` event) at no extra cost (MAP-3).
- **MOVE-8** A unit is **moving** for FIRE-5 when, at its most recent step of TIME-3a, it advanced its move progress (it had a move order, no current target and was not blocked). The flag is `unit.moving`; a shooter earlier in unit order reads the target's flag from the previous tick.

## 6. Sight (SEE)
- **SEE-1** Line of sight between two tiles on the same level follows the Bresenham line between their centres; it is blocked when any tile strictly between them is a `wall` or a closed `door`. Units, bodies, `window`, `rubble`, `void` and `ground` never block. There is no line of sight between levels.
- **SEE-2** A unit sees a tile when the tile is on its level, within its `sight` (MAP-5) and in line of sight (SEE-1). A unit always sees its own tile.
- **SEE-3** A side sees every tile that one of its living units sees. `civilian` sees nothing for rules purposes.
- **SEE-4** A side sees a unit when it sees that unit's tile. A side always sees its own units.
- **SEE-5** "Can currently see" in ORD-4 and section 13 means SEE-4 evaluated on the true state at that moment.
- **SEE-6** A diagonal line that passes exactly between two wall corners is not blocked (Bresenham visits no wall tile).

## 7. Disguise (HIDE)
- **HIDE-1** A `disguised` hostile (a host) that is not yet `revealed` appears to the agency as a citizen: in the agency's view (VIEW-2) it carries the `citizen` template, side `civilian`, no weapon, no orders.
- **HIDE-2** A host is revealed the moment it resolves a shot (FIRE-6), whether or not the shot hits.
- **HIDE-3** A host is revealed when, at TIME-3b, a living agency unit on its level has line of sight to it within `sight.revealRange = 3` tiles.
- **HIDE-4** Revealing is permanent and emits `revealed { unit, by: "fire" | "proximity" }`.
- **HIDE-5** Stance fire (STANCE-3) never targets a unit that appears to be a citizen to the shooter's side: agents never fire on their own at unrevealed hosts or at citizens. The hostile side has no disguise to see through.

## 8. Stances (STANCE)
- **STANCE-1** Stances: `engage` (fire at any eligible target), `retaliate` (fire only at eligible targets that have fired within the last `fire.retaliateMemoryTicks = 50` ticks), `hold` (never fire without an explicit target).
- **STANCE-2** Each template names its `defaultStance`: agents and hostiles `engage`, citizens `hold`.
- **STANCE-3** An **eligible** stance target for a unit is a living unit of an enemy side (agency vs hostile; citizens are never eligible, HIDE-5) that the unit itself sees (SEE-2), that is in weapon range (FIRE-1) and, for `retaliate`, whose `lastFiredTick` is within memory (`tick - lastFiredTick <= fire.retaliateMemoryTicks`, and it has fired at all).
- **STANCE-4** Among eligible targets the unit picks the nearest by MAP-5; ties go to the earliest in unit order (UNIT-3: agents first, then `u1, u2, ...`).

## 9. Fire (FIRE)
- **FIRE-1** A unit can fire at a target when it has a weapon, the target is a living unit of another side on its level, the shooter sees the target's tile (SEE-2), and the target is in range: Euclidean distance `<= weapon.range` for `ranged` weapons, Chebyshev distance 1 for `melee` weapons.
- **FIRE-2** A unit's **current target** at its step of TIME-3a is its explicit target (ORD-4) when FIRE-1 holds for it, otherwise its stance target (STANCE-3, STANCE-4), otherwise none. An explicit target that is down or no longer seen by the side is dropped; one that is merely out of range or out of the shooter's own sight is kept and waited for.
- **FIRE-3** With a current target and the weapon ready (`tick >= readyTick`), `aimProgress` rises by 1 per tick; when it reaches `weapon.aimTicks` the shot resolves in that same tick. A tick without a current target resets `aimProgress` to 0. With a current target but the weapon not ready, the unit waits (and stands, MOVE-4).
- **FIRE-4** Resolving a shot sets `readyTick = tick + weapon.cooldownTicks`, `lastFiredTick = tick`, `aimProgress = 0`, counts `score.shotsFired`, and reveals a disguised shooter (HIDE-2).
- **FIRE-5** Hit chance in percent: `raw = weapon.accuracy + shooter.aim - weapon.falloffPerTile * floor(distance) - (target moving ? fire.movingTargetPenalty : 0) - crouchPenalty + crouchBonus - runPenalty` (POSE-4), `fire.movingTargetPenalty = 15`; `chance = clamp(raw, fire.minHitChance, fire.maxHitChance)`, `fire.minHitChance = 5`, `fire.maxHitChance = 95`. Melee uses distance 0.
- **FIRE-6** The roll is one RNG integer `0..99`; the shot hits when `roll < chance`.
- **FIRE-7** A miss never hits its target. Since section 28 it may hit a unit beside the target (STRAY-1); otherwise a missed ranged shot may strike structure behind the target (STR-6).
- **FIRE-8** A hit applies damage (section 10) to the target.
- **FIRE-9** Every shot emits `shot { shooter, target, weapon, distance, moving, breakdown: { accuracy, aim, falloff, movingPenalty, crouchPenalty, crouchBonus, runPenalty, raw, chance }, roll, hit }`.

## 10. Damage (DMG)
- **DMG-1** Raw damage is one RNG integer in `weapon.damageMin..weapon.damageMax` inclusive.
- **DMG-2** Damage dealt is `max(0, raw - target.armour)`.
- **DMG-3** `hp` falls by the damage dealt and never below 0. At 0 the unit is down (UNIT-4) and a `down` event follows the `damaged` event; the side counters `score.agentsDown`, `score.hostilesDown`, `score.civiliansDown` rise.
- **DMG-4** Every hit emits `damaged { unit, raw, armour, dealt, hp }` and `score.hits` rises; a taking hit (TAKE-1) emits `taken` instead of `damaged` and rolls no damage.

## 11. Citizens (CIV)
- **CIV-1** Citizens never move, fire or take orders in this slice; they stand where they spawned (a taken citizen is a host from then on, TAKE-1).
- **CIV-2** Citizens block movement like any living unit and never block sight.
- **CIV-3** `score.civilianHits` rises on every hit on a unit that appears to be a citizen to the agency at that moment (a real citizen, or a host not yet revealed); `score.civiliansDown` counts real citizens only.

## 12. End of battle (END)
- **END-1** The agency wins when no living hostile unit remains: `over = { winner: "agency", reason: "cleared", tick }`.
- **END-2** The hostiles win when no living agency unit remains: `winner: "hostile", reason: "squad-lost"`. When both END-1 and END-2 hold after the same tick, `winner: "none", reason: "mutual"`.
- **END-3** When `tick >= time.maxBattleSeconds * time.ticksPerSecond` with no winner, `winner: "none", reason: "timeout"`; `time.maxBattleSeconds = 600`.
- **END-4** `withdraw` ends the battle with `winner: "none", reason: "withdrawn"` (what a withdrawal costs is the city layer's business, M7).
- **END-5** Once `over` is set it never changes; every order is rejected (ORD-2) and `tick` is a no-op (TIME-5). An `over` event is emitted once.

## 13. View (VIEW)
- **VIEW-1** `view(state, side)` returns a `State` that holds the side's own units in full and keeps tiles, tick, tuning, score and `over`.
- **VIEW-2** Units of other sides appear only while the side can currently see them (SEE-5), **redacted**: `order: null`, `fireTarget: null`, `aimProgress: 0`, `readyTick: 0`, `lastFiredTick: -1`, `stance: "hold"`, `blast: null`, `charges: 0`; a disguised, unrevealed host additionally shows template `citizen`, side `civilian`, `weapon: null`, `disguised: false` and the citizen template's name (HIDE-1). Position, `moving`, `hp`, `maxHp`, `armour`, `aim`, `moveTicks`, `sight`, `revealed`, `down`, `posture` and `lastRunTick` are shown as they are (the suit says what it is; a crouch and a run are seen).
- **VIEW-3** Down units of other sides are shown while their tile is seen, redacted the same way.
- **VIEW-4** The view's `rng` is `[0, 0, 0, 0]` and its `log` is empty, so no side can foresee a roll or read the other side's orders. `civilian` sees only its own units.
- **VIEW-5** When at least one and at most `sight.markLastHostiles = 2` hostile units are living, `view(state, "agency")` carries `marks`: the tile `{ x, y, level }` of each such hostile the agency cannot currently see, in unit order (seen ones are already in `units`). A mark is a place, not a unit: it names no id, template or side, and it gives no right to fire (ORD-4 still needs sight). No other view and never the true state carries `marks`.

## 14. Queries (QRY)
- **QRY-1** `query.seconds(state)` = `tick / time.ticksPerSecond`; `query.ticksFor(state, seconds)` = `round(seconds * time.ticksPerSecond)`.
- **QRY-2** `query.hitChance(state, shooterId, targetId)` returns the FIRE-5 breakdown with `chance`, or `{ ok: false, reason }` when FIRE-1 fails; `query.damageRange(state, shooterId, targetId)` returns `{ min, max }` after armour.
- **QRY-3** `query.reachable(state, unitId)` lists every tile the unit can path to with its cost in ticks (MOVE-2), excluding tiles held by living units; `query.path(state, unitId, to)` returns `{ steps, ticks }` or `null`.
- **QRY-4** `query.canSee(state, side, unitId)`, `query.visibleTiles(state, side)` and `query.los(state, a, b)` expose section 6; `query.distance(a, b)` exposes MAP-5.
- **QRY-5** `query.outcome(state)` returns the counters of `state.score`, living counts per side and `over`.
- **QRY-6** `query.unitsSeen(state, side)` lists the ids of units the side can see (SEE-4).
- **QRY-7** `query.tileInfo(state, pos)` returns `{ kind, open, material, materialName, hp, maxHp, breakable }` (STR-1, STR-2) or `null` off the map.
- **QRY-8** `query.blastPreview(state, unitId, at)` returns `{ ok: true, armTicks, tiles: [{ x, y, level, structureDamage, unitDamage }] }` for the centre and its neighbours (BLAST-3, BLAST-4), or `{ ok: false, reason }` when ORD-9 fails.
- **QRY-9** `coverAt(state, side, tile)`: the cover a tile would give against the nearest hostile the side sees on that level (COVER-1, COVER-2), with that hostile's id; null when none is seen. The file card shows it for the selected agent.

## 15. Save (SAV) - engine side (SAV-1, SAV-2) and client side (SAV-3..SAV-6, M2; `PLAN.md` D13, Q5; KB rule 22)
- **SAV-1** The save snapshot is `state` itself (ARCH-6). A battle reopens by loading the snapshot; the action list rides along for replay (`replay(setup, log)` equals the snapshot, ARCH-9).
- **SAV-2** Autosave points for M2: every pause, every accepted order and every `save.autosaveSeconds = 10` seconds of sim time. The engine only supplies the number.
- **SAV-3** The client keeps one save under the `localStorage` key `ekc-save`: an envelope `{ game: "ekc", version: 1, savedAt, reason, setup, snapshot, tileDiff, hash, log, paused: true, selected, level }`. `snapshot` is the state with its `tiles` emptied, `tileDiff` lists every tile that differs from the map file as `[index, kind, open, material, hp]`, `hash` is `hashState` of the full state and `log` equals `snapshot.log`. Loading rebuilds the tiles from the map file, applies the diff and checks the hash. It is written when a raid starts (before its first frame), at every SAV-2 point and when the player leaves the battle screen.
- **SAV-4** Continue reopens the snapshot **paused**, with the saved selection and level, without replaying; the title screen names what it reopens: the battle, the sim seconds, agents standing out of the squad, hostiles down and the time saved. Discard asks once more before clearing.
- **SAV-5** A finished battle clears its save the moment `over` is set; the report is shown from memory.
- **SAV-6** Never silent: a save that is not readable JSON, of another version, for a battle or map this build lacks, with an incomplete snapshot, or whose rebuilt state does not match its hash (the map file changed) is reported on the title screen by reason, with Discard offered; a storage that refuses a write is reported in the console strip and the battle plays on unsaved.

## 16. Invariants (INV) - checked by `sim` and `action-fuzz` after every step
- **INV-1** `legalActions(state, side)` is never empty for any side (ARCH-3).
- **INV-2** `0 <= hp <= maxHp` for every unit; a unit is down exactly when `hp = 0`.
- **INV-3** No two living units share a tile; every unit, standing or down, is on a passable tile that exists (a collapse moves it, STR-5); every tile carries an integer level in `0..levels-1`.
- **INV-4** `tick` never decreases and increases by exactly 1 per accepted tick while the battle is not over.
- **INV-5** `JSON.parse(JSON.stringify(state))` deep-equals `state`; the JSON text contains no `NaN`, `Infinity` or `undefined`.
- **INV-6** `view(state, side)` contains no unit the side cannot see and no field VIEW-2 redacts.
- **INV-7** `replay(setup, state.log)` hashes to `hashState(state)` (checked at the end of every sim battle).
- **INV-8** For every tile `0 <= hp <= ` its material's `hp`; a breakable tile (STR-2) never rests at `hp = 0`; `rubble` and `void` tiles carry material `none`. For every unit `charges >= 0`, and a pending charge names a tile on the unit's level.

## 19. Structure (STR) - `PLAN.md` D16: walls and floors are destructible from M2
- **STR-1** Every tile carries a `material` (an id in `src/data/materials.json`) and `hp`. A map names materials per tile through an optional `levels[].materials` grid, one character per tile, read through the map's `materialKey`; a tile without one (or with a space there) takes the default material of its kind (`materials.json` `_defaults`). `hp` starts at the material's `hp`.
- **STR-2** A tile is **breakable** when its kind is `wall`, `door`, `window` or `floor` and its material's `hp` is above 0. `ground`, `rubble`, `void` and, since M3, `stair` are never damaged (RULING STR-2).
- **STR-3** Structure damage of `amount` on a breakable tile lowers its `hp` by `amount`, never below 0, and emits `tileDamaged { at, amount, hp }`. At `hp = 0` the tile is destroyed (STR-4). Damage on an unbreakable tile does nothing and emits nothing.
- **STR-4** A destroyed `wall`, `door` or `window` on any level, and a destroyed `floor` on level 0, becomes `rubble`. A destroyed `floor` above level 0 **collapses** into `void` (STR-5). The new tile has material `none`, `hp = 0`, `open = false`; `tileDestroyed { at, was, now }` is emitted. Nothing else changes: there is no chain collapse.
- **STR-5** When a floor collapses, every unit on it, standing or down, drops to the tile directly below. A living unit takes `structure.fallDamage = 15` (armour does not apply), loses its move order, pending charge and aim, and `fell { unit, from, to, dealt, hp }` is emitted, followed by `down` at 0 hp (DMG-3 counters). The collapse needs the tile below to be passable and, for a living unit, free of a living unit; when a unit on the tile could not land, the floor **holds at `hp = 1`** instead.
- **STR-6** A ranged shot that misses flies on: along the line from the shooter through the target (Bresenham from the target's tile), out to the weapon's `range` from the shooter, the first `wall`, closed `door` or `window` tile it meets takes `weapon.structureDamage` (STR-3). A weapon with `structureDamage = 0` and every melee weapon strikes nothing.

## 20. Charges (BLAST) - the first explosion (`PLAN.md` D16)
- **BLAST-1** A unit starts with its template's `charges` (agents carry 2, fighters 1 since M3, hosts 1 and spitters 3 since D26 slice 3 (STRAY-3), everyone else 0). `unit.blast` is its pending charge `{ at, progress }` or `null`; `blast` (ORD-9) sets it with `progress: 0`.
- **BLAST-2** At its step of TIME-3a a living unit with a pending charge stands still (`moving` false, aim reset, move order kept) and `progress` rises by 1. At `blast.armTicks = 6` the charge detonates in that tick: `charges` falls by 1, `blast` clears and `lastFiredTick = tick`.
- **BLAST-3** A detonation at `at` emits `blast { unit, at }`, then deals structure damage (STR-3): `blast.structureDamage = 160` to the centre tile and `blast.edgeStructureDamage = 60` to each of its eight neighbours on the level, in the order centre, E, S, W, N, NE, SE, SW, NW.
- **BLAST-4** Before the structure damage, every living unit on the centre tile takes `blast.unitDamage = 40` less its armour and every living unit on the eight neighbours `blast.edgeUnitDamage = 20` less its armour, in unit order, whatever its side: `damaged` and `down` events and the DMG-3 counters follow, `score.civilianHits` rises as in CIV-3, `score.hits` and `score.shotsFired` do not change.
- **BLAST-5** A blast reveals no host and a host caught in one stays disguised (as HIDE-2 for hits).

## 21. Taking (TAKE) - M3: how the organism makes hosts (`docs/GAME-DESIGN.md` 3; `PLAN.md` D6, D14)
- **TAKE-1** A weapon may name `takes`: the template a living **real citizen** becomes when the weapon hits it (`weapons.json`; the taker's bite takes `host`; only a melee weapon may take, `validate:data`). A taking hit deals no damage and rolls none (DMG-1 is skipped): the citizen is converted in place. It keeps its id, tile, `hp` and `maxHp` (RULING UNIT-5 keeps host and citizen hp equal) and takes the new template's `template`, `name`, `side`, `armour`, `aim`, `moveTicks`, `sight`, `weapon`, `disguised`, `defaultStance` and `charges`; its move order, explicit target, aim and pending charge are cleared, `readyTick` becomes the current tick and `moving` false.
- **TAKE-2** The new host is `revealed` when a living agency unit sees the citizen's tile at that moment (SEE-4), and hidden otherwise. The event is `taken { unit, by, seen }` in place of `damaged`.
- **TAKE-3** `score.taken` rises by 1; `score.hits` and `score.civilianHits` rise as for any hit on an apparent citizen (CIV-3); `score.civiliansDown` does not change. The new host counts as a living hostile for END-1 and END-2 from that tick.
- **TAKE-4** A taking weapon's hit on anything but a real citizen (an agent, a host, a fighter) is an ordinary hit (section 10). Citizens are never stance targets (STANCE-3), so a taking happens only on an explicit `fire` order at the citizen (the AI's, AI-5, or a random one).

## 22. AI (AI) - M3: how the hostiles play (`PLAN.md` D14, M3)
- **AI-1** The AI lives under `src/ai/`, outside the engine, imports nothing from the DOM, three.js or React, and is handed `view(state, side)` only (ARCH-5): it knows its own units in full, the enemy and civilian units its side currently sees (redacted, VIEW-2), every tile (VIEW-1), the tick and the score, and nothing else. The hostile drivers are pure functions of the view: the same view gives the same orders, so a replay of the log reproduces the AI. Its orders go through `step` like the player's (ORD-1..9); a rejected order is dropped.
- **AI-2** Difficulties: `random` and `normal` (`src/ai/index.ts`, `makeAi(side, difficulty)`). The client runs the hostile `normal`; `?ai=random` or `?ai=none` on the page changes it (`none`: the hostiles act by stance alone, as in M2) for flow tests and playtests. The level is not part of the state or the save.
- **AI-3** Reaction window: a side's AI decides every `ai.decideTicks = 5` ticks (half a second) for every living unit of the side in id order, and never between windows. A unit keeps a move order whose destination lies within two tiles of its new goal, and a fire order on the same target is not re-issued (a re-issued move order would reset its progress, MOVE-3).
- **AI-4** Hosts (`normal`): while disguised and unrevealed they take stance `hold` and stand where they are, passing as citizens (a hidden host never walks toward agents); they open fire (an explicit `fire`, which reveals them, HIDE-2) when an agent they can fire at (FIRE-1) is within `ai.hostAmbushRange = 4` tiles, choosing the agent with the least hp, and once committed keep `engage`. Revealed, they fight from a firing position (AI-6) at about the ambush range, firing at the agent in reach with the least hp. A revealed host below `ai.fleeHpPercent = 40` percent of its hp, or watched by three or more agents with no other hostile within 8 tiles, runs with stance `hold` to the tile within 40 ticks of walking that no known agent sees and lies farthest from them, as long as a hostile above that hp share is still in the fight; the last of them fight to the end. When no agent is in sight and `ai.huntAfterAgentsDown = 3` or more agents are down, hidden hosts leave their posts and roam.
- **AI-5** Takers: stance `engage`. A taker charges the most isolated known agent (fewest agents within `ai.isolationRange = 5` tiles of it, then the nearest) when that agent is within `ai.takerChaseRange = 12` tiles and has at most two agents near it, or two hostiles stand within 8 tiles of the taker, or it is within three tiles already: it takes an explicit `fire` on the agent and walks to a free tile beside it, so the bite lands on arrival (FIRE-2 keeps an out-of-range target). Otherwise it seeks the nearest citizen it sees and takes it the same way (TAKE-1). Otherwise it walks to within three tiles of the nearest host and guards it until the hunt begins (`ai.huntAfterAgentsDown = 3` agents down, or `ai.huntAfterSeconds = 120` seconds of battle); then, or with no host left, it roams.
- **AI-6** Fighters: stance `engage`. A fighter fires at the agent in reach with the least hp. A fighter that sees two or more agents within a tile of one another inside `blast.throwRange`, with no hostile beside them, throws its charge at them first (ORD-9, BLAST-4). A **firing position** against a target is a tile on the target's level within the weapon's range, not adjacent to it, with line of sight to it, seen by as few agents as possible, close to a preferred distance (one tile inside whip range), within `ai.coverSearchTicks = 30` ticks of walking; a fighter shifts to one when it is exposed to two or more agents or below the flee share, and when two or more agents see it with no other hostile within 8 tiles it breaks line of sight instead (a fighter beats one agent and loses to two). Against a straggler it advances to a firing position; against three or more agents together with fewer than two hostiles within 8 tiles, it slips to a tile they cannot see and waits for them to spread. When the nearest agent on its level is within `ai.breachRange = 8` tiles as the crow flies but no firing position is in reach and the path to a tile beside the agent is longer than `ai.breachDetourTicks = 40` ticks or does not exist, it throws its charge (BLAST-1) at the first wall, window or closed door on the straight line to the agent that ORD-9 allows. Agents known on another floor draw it to them through the stairs (MAP-4). With nothing known it guards the nearest host within five tiles until the hunt begins (as AI-5), then roams.
- **AI-7** `random`: in every window each living unit of the side, with `ai.randomOrderPercent = 50` percent chance, takes one order drawn from the AI's own sfc32 stream seeded from the battle seed, the tick, the side and the unit id (never the engine's RNG, ARCH-7): a move to a tile within 30 ticks (twice as likely as the others), a `fire` at a unit of another side in its view, a stance change, or a charge at a tile it can see. Never `withdraw`. It is the floor the bench measures `normal` against and a rules fuzzer in its own right.
- **AI-8** The agency `normal` driver (the bench's other seat and the squad's self-defence pattern) keeps a memory of checked citizens and tiles seen: agents fire at the hostile in reach with the least hp from a firing position two tiles inside their weapon's range, advance on a hostile only with another agent within four tiles (regrouping otherwise) (out of a whip's or a bite's reach where the map allows), walk up to every apparent citizen to within `sight.revealRange` (HIDE-3), then sweep to the nearest tiles never seen, and start the sweep again when nothing is left. The client never runs it.
- **AI-9** The client gives the hostile AI its turn before each tick inside `advance` (`src/ai/drive.ts`, `advanceWithAi`; TIME-6): pause is still the absence of ticks, so a paused battle gets no AI order, and the AI's orders are in `state.log` (ARCH-9), so Continue (SAV-4) and `replay` reproduce them. The message tray never prints a hostile order (VIEW-2), nor a door opened on a tile the squad does not see, and reports a taking only when the squad watched it (TAKE-2); the console's counters do not show takings during the battle (the report does, after it).
- **AI-12** (2026-11-22) Both `normal` drivers prefer firing tiles with cover against their target (half the cover's value in the tile's score), crouch when they fire from a tile that has cover against their target, and stand before they move.
- **AI-13** (2026-11-22) The `normal` agency driver lays suppressive fire on a target it can fire at when its aimed chance is under `suppress.aiBelow = 30` (SUP-3); a `normal` fighter that is pinned (SUP-4) with no cover against its target breaks line of sight before anything else.
- **AI-14** (2026-11-22) A `normal` spitter throws at two or more agents within its throw, otherwise closes to one tile inside throwing range keeping out of sight, and hides once its charges are spent; a revealed host with its charge throws it at three or more agents together; both `normal` drivers score a firing tile 6 lower for each friend beside it, so squads spread out (12 cost the bench a battle in 200; 6 holds it).
- **AI-10** Bench: `npm run bench:ai` plays `bench-raid` (6 agents against 4 hosts, 2 takers, 2 fighters and 4 citizens on `civic-savings-branch`, a roster chosen so that `random` against `random` is near even) over seeded battles in both seats (normal hostiles against random agents, then normal agents against random hostiles, alternating seeds), with the invariants of section 16 checked after every step, and prints the normal side's win rate per seat and overall; a draw (timeout or mutual) is not a win. The gate (`PLAN.md` M3) is at least 95 percent over at least 200 battles, and the same seed in the same seat must replay to the same hash. The result is recorded in section 23.

## 24. Posture and pace (POSE) - M4c: crouching and running (`PLAN.md` D21 c)
- **POSE-1** A unit has a `posture`, `stand` or `crouch`, and starts standing. `unit.lastRunTick` is the last tick it advanced a running move, or `null`. A state from before M4c has neither field: it reads as standing and never having run.
- **POSE-2** `posture` (ORD-1) is legal for a living own unit and a posture other than its current one. It sets `unit.posture`. Crouching turns a running move order into a walk. A `move` with `run: true` stands a crouched unit up.
- **POSE-3** A `move` may carry `run: true`; the order keeps it as `order.run`. A step of a running order costs `round(cost * move.runCostPercent / 100)`, `move.runCostPercent = 60`. A step of a crouched unit costs `round(cost * move.crouchCostPercent / 100)`, `move.crouchCostPercent = 150`. Both apply after MOVE-2, and no step costs less than 1 tick. Paths are planned with the same costs.
- **POSE-4** FIRE-5 gains three terms (and section 25 a fourth, `cover`), each shown in the breakdown:
  - `crouchPenalty`, `fire.crouchTargetPenalty = 15`, when a ranged shot's target is crouched and at least 2 tiles away;
  - `crouchBonus`, `fire.crouchAimBonus = 5`, when the shooter of a ranged shot is crouched;
  - `runPenalty`, `fire.runningShooterPenalty = 20`, when the shooter ran within the last `fire.runSettleTicks = 10` ticks (`tick - lastRunTick < runSettleTicks`).
  
  Melee ignores crouching.
- **POSE-5** Every unit that advances its move progress on a running order sets `lastRunTick = tick`, whether or not it completes the step that tick (TIME-3a).

Posture and pace (section 24, D21 c), 2026-11-20: **unchanged**: 95.0% (190/200) on `bench-raid` with the same per-seat rows; 85%, 80% and 85% on the three sites. Neither the AI nor the bench's random agents give posture or run orders yet (RULING POSE-1), so the new terms never apply there. The AI slice that teaches cover and pace needs its own result.

## 29. Objectives with a clock (OBJ) - 2026-11-22, `PLAN.md` D26 (4)
- **OBJ-1** **Capture:** when the battle's roster allows it (`roster.capture`, the city's restraints; `state.canCapture`), `{ type: "capture", side, unit, target }` starts a capture of a revealed host or taker beside the agent (Chebyshev 1, same level) at no more than `objective.captureHpPercent = 50` percent of its health. While the target stays beside it the agent neither moves nor fires; after `objective.captureTicks = 10` ticks the target is **captured**: it leaves the field (down, `captured`, no body), counts in `score.hostilesDown` and `score.captured`, and emits `captured`. Any move, fire, suppress or halt order ends a capture.
- **OBJ-2** **Evacuation:** `{ type: "evacuate", side, unit, target }` sends a citizen beside the agent running (POSE-3) by the shortest path to the nearest free tile on the map's ground-level edge; it emits `evacuating`. A citizen evacuates once.
- **OBJ-3** An evacuating citizen who reaches the edge is **saved**: it leaves the field (down, `saved`, no body; not a civilian down) and counts in `score.saved`. Takers and stray rounds still catch it on the way.
- **OBJ-4** **The core:** a battle file may name a `core` tile (the wreck's drive). An agent standing on it adds one to its progress each tick; at `objective.coreTicks = 30` it is **secured** (`coreSecured`). If it is not secured by `objective.burnSeconds = 90` seconds, the wreck burns and the core is lost (`coreBurnt`). Neither ends the battle.
- **OBJ-5** `legalActions` lists, for each agent, an evacuate order for each citizen beside it that is not evacuating, and a capture order for each target OBJ-1 allows.

## 28. The price of standing together (STRAY, PANIC) - 2026-11-22, `PLAN.md` D26 (3)
- **STRAY-1** A missed ranged shot may hit someone else: of the living units on the target's level within one tile of it (Chebyshev 1), not the shooter or the target, that the shooter can see (SEE-2), one roll in 100 under `stray.percent = 25` picks one uniformly (a second roll) and hurts it with the weapon's damage roll (DMG-1). Own side and citizens included. It emits `strayHit { shooter, target, victim, roll }`; a citizen hit counts as a civilian hit (CIV-3). With no such unit, or the roll failed, the miss strikes structure as before (STR-6).
- **STRAY-2** A stray hit is not a hit in `score.hits` and does not suppress (SUP-1 counts only the shot at the target).
- **STRAY-3** The **spitter** (`units.json`): a pearl sac on chitin legs with no gun and `charges` 3: it lobs spore sacs, the charge of section 20, at agents standing together. A revealed **host** carries one charge. Neither change touches the charge's rules.
- **PANIC-1** When a non-civilian unit goes down, every living ally on its level within `panic.range = 3` tiles with line of sight to it gains `panic.amount = 40` suppression (SUP-1, capped).

## 27. Suppression (SUP) - 2026-11-22, `PLAN.md` D26 (2): fire and move
- **SUP-1** Every unit carries `suppression`, 0 to `suppress.cap = 100` (0 in saves from before). A ranged shot at a unit, hit or miss, adds `suppress.perShot = 20`, and a hit `suppress.perHit = 15` more; citizens are never suppressed. At the end of every tick's unit steps (TIME-3a) every unit's suppression falls by `suppress.decayPerTick = 3`, not below 0.
- **SUP-2** FIRE-5 gains the term `suppressPenalty`: `floor(shooter.suppression * suppress.aimPercent / 100)` (`suppress.aimPercent = 30`), shown in the breakdown.
- **SUP-3** `{ type: "suppress", side, unit, at }` lays **suppressive fire** on a tile: legal for a unit with a ranged weapon when the tile is on its level, within the weapon's range and seen by the unit (SEE-2). It replaces the unit's move and fire orders (a new suppress order on a unit already suppressing keeps its aim progress); a later move, fire or halt order ends it, and so does the tile leaving sight or range. While it holds, the unit does not move; each time its weapon is ready it aims as for a snap shot (SNAP-1) and fires a burst: no roll and no damage, but every non-civilian enemy on the tile or beside it (Chebyshev 1) gains `suppress.fire = 20`. The burst counts as a shot fired (FIRE-4: cooldown, `lastFiredTick`, reveals a disguised shooter) and emits `suppressFire { unit, at, weapon, pinned }`.
- **SUP-4** A unit at `suppress.pinnedAt = 60` or more is **pinned**: its move order makes no progress on odd ticks (half pace).
- **SUP-5** `legalActions` lists one suppress order per unit, at the tile of the nearest seen non-civilian enemy it can suppress (SUP-3); any other tile it can suppress is still accepted by `step`.

## 26. Aimed and snap shots (SNAP) - 2026-11-22, `PLAN.md` D26 (1): orders decide fights
- **SNAP-1** A ranged shot at a **stance target** (FIRE-2: no explicit fire order on that target) is a **snap shot**: it aims for `snap.aimPercent = 50` percent of the weapon's `aimTicks` (rounded up, at least 1). A shot at the unit's ordered target (ORD-4) aims for the full `aimTicks`. Melee is never a snap.
- **SNAP-2** A snap shot's hit chance loses `snap.penalty = 25` (FIRE-5's term `snapPenalty`, shown in the breakdown; 0 on an aimed shot).
- **SNAP-3** `query.hitChance` (QRY-2) gives the chance of an aimed shot, the one a fire order makes; the console says so.

## 25. Cover (COVER) - 2026-11-22: what stands beside a target makes it harder to hit
- **COVER-1** A target's **cover tiles** against a shooter are its neighbours on the shooter's side: the east or west neighbour when the line's run along x is at least half its run along y, the north or south neighbour when the run along y is at least half the run along x, and the diagonal neighbour between them when both are. A shooter straight east of the target looks only at the east neighbour; one at 45 degrees at all three.
- **COVER-2** A cover tile gives **full** cover when it is a `wall` or a closed `door`, **half** cover when it is a `window`, **low** cover when it is `rubble` or a `floor` or `ground` tile under a solid prop (COVER-3). A tile gives nothing otherwise. The target takes the best grade among its cover tiles. A wall that stands on the line itself still blocks sight (SEE-1); full cover is the wall a shot passes around, at a corner or a doorway.
- **COVER-3** The solid props are `desk`, `counter`, `shelf`, `bed`, `locker`, `machine`, `bench`, `vehicle`, `planter`, `tank` and `crate` (`COVER_PROPS` in `src/data/index.ts`); lamps, signs, masts and vents give none. A prop gives cover only while its tile is still `floor` or `ground`, as the board draws it (MAP-9): a tile that breaks to rubble gives rubble's low cover, one that collapses to `void` gives none. This is the only rule that reads a prop (RULING MAP-9).
- **COVER-4** FIRE-5 gains the term `cover`, shown in the breakdown with its `coverGrade`: `cover.full = 40`, `cover.half = 25` or `cover.low = 20` off a ranged shot's hit chance, before the clamp. A shot from an adjacent tile (Chebyshev distance 1) and every melee attack ignore cover. Cover stacks with crouching (POSE-4).
